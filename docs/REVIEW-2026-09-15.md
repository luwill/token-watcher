## 1. 产品功能评审

### 1.1 从真实数据看当前体验

用本机运行数据走了一遍面板，几个直观感受：

- **花费卡是全站最有信息量的卡，但口径混在一起。** `costs.by_tool` 里 claude-code ¥29,793、codex ¥25,263 都是"API 等值"（假设性），ccmr ¥57 是实付。卡片底部一行小字"ccmr 为实付 · 订阅工具为 API 等值成本"承担了全部解释责任，容易被忽略。
- **对账卡在误导。** DeepSeek 24h 余额下降 ¥2.77，卡片显示"统计 -0.00 ¥"并打 ⚠。用户第一反应是采集漏了，实际是对账函数的口径 bug（见 3.1 H2）。
- **两个模型未配价被折叠成一句"⚠ 2 个模型未配价"**（`qwen3.8-flash-next`、`codex-auto-review`），要悬停才知道是谁、也没有入口去配。
- **范围选择器的作用域不一致。** 切到"90 天"后：按天消耗/花费/模型 Top10 跟着变，"模型工具调用"固定近 30 天（`web/app.js:480` 硬编码），花费卡只有今日/近 7 天，热力图固定一年。用户很难建立"这个按钮控制什么"的心智模型。
- **会话钻取是最有深度的功能，却在最后一步断掉**：曲线出来了，悬停没有任何反馈。

### 1.2 功能建议（按价值排序）

#### P0：先修再加

1. **修复对账与会话曲线两处 bug**（代码侧 H2、H3）。这两处直接影响"数据可信"这一核心价值。
2. **订阅 ROI 面板。** 已有全部原料：按工具的 API 等值成本、按天序列。缺一个"订阅实付"输入（每工具月费，写在 `pricing.json` 或新的 `config.json`），即可给出"本月 API 等值 ¥X vs 订阅 ¥Y，节省 Z 倍"与逐月趋势。这是 Token 面板类工具里最能让用户截图分享的一张卡，也回答了"我该不该续订"的真实问题。
3. **配置文件 + 环境变量。** 目前 `src/config.js:13-70` 的七个 roots、`DEFAULT_PORT`、菜单栏阈值（80%/95%、¥10/¥2）、菜单栏轮询地址（`menubar/main.swift:7` 硬编码 8787）全部写死。建议：
   - `~/.tokenmeter/config.json`：`sources.<tool>.roots / enabled`、`port`、`alerts`、`subscriptions`、`offline`
   - 尊重上游环境变量：Claude Code 的 `CLAUDE_CONFIG_DIR`、Codex 的 `CODEX_HOME`（目前 `grep` 全仓库无引用，用了自定义目录的用户会看到"无数据"）
   - `tokenmeter serve --port` 与菜单栏共享同一配置
4. **项目维度。** `project` 已经在每条事件里，加一张"按项目 Top N（token / 花费）"横条图和会话表的项目筛选，成本很低，价值很高（回答"哪个项目最烧钱"）。

#### P1：让现有功能闭环

5. **范围选择器一致化。** 工具调用榜跟随范围；花费卡加"本范围"一栏；模型 Top10 超出部分显示"其他"（后端 `src/server.js:151` 的 `LIMIT 10` 会把长尾直接丢掉，与前端花费图"聚合不丢数据"的口径不一致）。
6. **自定义日期区间 + 环比。** 卡片上加"较上一周期 ±x%"，趋势图支持拖选区间。
7. **告警统一。** 目前只有菜单栏 App 有阈值通知，Web 端没有；数据源 `error/stale` 状态也不进通知。建议告警逻辑放后端（`/api/alerts` 或 SSE 事件），Web 与菜单栏都只做展示；阈值可配。
8. **网络透明度与离线模式。** README 隐私段写"不上传任何数据"，这是真的，但服务会主动访问四类外网端点：汇率（`src/fx.js:10-13` 两个免费接口）、LiteLLM 牌价（GitHub raw，2MB）、厂商余额接口（带 API key 的 Bearer 请求）、以及 npm 安装时的 ECharts。建议在 README 明确列出"出站请求清单"，并提供 `--offline` / `config.offline`（跳过 fx/litellm/balance，用本地缓存与 `pricing.json`）。这也顺便解决测试依赖公网的问题。
9. **Codex 配额展示补全。** 真实 `rate_limits` 结构里有 `secondary`（周窗口时为 5h 窗口）与 `credits.balance`，采集器 `src/collectors/codex.js:62-70` 只存 `primary`。建议两个窗口都存都显示。
10. **Claude 5h 窗口推算对齐 ccusage。** `src/server.js:60-81` 按会话分块；ccusage 的 session-blocks 是全局（跨会话）按时间排序、块起点向下取整到整点。两者在多会话并行时结果会明显不同。既然卡片标了"推算"，至少和被引用的算法一致；长期看应寻找官方口径来源。
11. **导出增强。** 目前只有日×工具的 CSV。加逐事件 JSON/CSV（可选脱敏 project）、按范围导出、以及"导入合并"以支持多机汇总。
12. **CLI 补齐。** `--help`、`--version`、`tokenmeter status`（服务是否在跑、各源健康）、`tokenmeter sources`（各源路径与文件数）。`npm run install-agent` 依赖一个仓库里不存在、需要用户手写绝对路径的 plist（本机那份指向 `/usr/local/bin/node` 与开发目录），对 `npx` 用户不可用。改为 `tokenmeter install-agent` 用 `process.execPath` 与解析后的脚本路径生成 plist。

#### P2：打磨

13. **命名统一。** 同一产品出现四个名字：包名/README `token-watcher`、CLI/数据目录/launchd label `tokenmeter`、菜单栏 `Info.plist` 显示名 `Token Stats`、仓库目录与 `.gitignore` 里的 `token-stats`。选一个，其余做别名迁移。
14. **浅色主题 / 跟随系统、英文界面**（Roadmap 已列）。
15. **会话钻取增强**：单会话成本、复制 session id、显示 transcript 路径；曲线区分输入/缓存/输出三段。
16. **未配价模型可操作**：未配价列表可点开，一键写入 `pricing.json` 模板。

## 2. 代码评审

### 2.1 总体印象

优点：

- **口径与幂等性设计成熟**：dedup_key 全局唯一 + `INSERT OR IGNORE`、采集器版本号触发回填、Codex 差分与 resume 链继承（`src/scanner.js:135-165`）都有对账验证。
- **零依赖坚持得很好**：后端只用 Node 内置模块，前端零构建。
- **文档质量高**：`docs/ARCHITECTURE.md` 的数据源格式笔记与 ECharts 踩坑记录，`learnings/` 的复盘，都是真正能帮下一个人的内容。
- **测试有真实价值**：fixtures 黄金数字 + 二次扫描幂等 + API 结构，抓过"误删 renderLive"这类事故。

短板集中在三处：**健壮性边界**（进程会因文件竞争退出、路由无错误处理）、**前端与测试的结构**（单文件 911 行，测试靠正则抽源码）、**若干口径 bug**。

### 2.2 问题清单

#### HIGH（应在下个版本前修复）

**H1. 扫描期间文件被删除会让服务进程退出。（✅ 已修）** `src/scanner.js:85` 的 `await stat(path)` 在 `try` 之外；`enumerate` 是惰性生成器，`readdir` 列出后逐个处理，中间任意文件被删就抛 `ENOENT`，`scanAll` 整体 reject。调用方 `_scheduleScan`（`src/scanner.js:192-195`）在 `setTimeout` 回调里 `await` 且无 catch，Node 默认对未处理 rejection 直接退出进程。launchd `KeepAlive` 会拉起，因此这类退出在本机只表现为日志里多一行启动记录（两天内已有 17 次 `db:` 启动行，其中 12 次是模块级错误导致的崩溃重启，说明"崩了再拉起"确实在发生），`npx token-watcher serve` 在终端里则直接死掉。文件删除并不罕见：Claude Code 有会话清理策略、Codex 归档会把文件从 `sessions/` 搬到 `archived_sessions/`，真实库 `files` 表已有 40 条路径不存在的陈旧行（claude-code 35、grok 4、codex 1）。
修法：`stat` 放进 `try`，`ENOENT` 视为"文件已删"跳过并标记；`_scheduleScan` 里 `.catch(log)`；进程级加 `process.on('unhandledRejection')` 兜底记录。

**H2. 余额对账只认 CNY 计价，DeepSeek 统计花费恒为 0。（✅ 已修）** `src/pricing.js:166` 要求 `p.currency === 'CNY'`，而种子表与用户 `pricing.json` 里 DeepSeek 全是 USD；同时只查本地表不查 LiteLLM（`computeCosts` 已经会查）。实测 `/api/summary` 返回 `{"id":"deepseek","delta":-2.77,"spend":0}`，前端据此打 ⚠。
修法：对账复用 `priceOf()`（含汇率折算与 LiteLLM 回退），按 provider 前缀过滤模型即可；`PROVIDER_PREFIX` 加 glm。

**H3. 会话钻取曲线悬浮框永远不出现。（✅ 已修）** `web/app.js:550-556` 的 tooltip 未设 `trigger:'axis'`（默认 `item`），而 `web/app.js:560` 的折线 `symbol:'none'` 没有可命中的图元。`learnings/2026-09-15-echarts-tooltip-clipped-by-overflow-hidden.md` 已确认这是既有 bug 但当时刻意不夹带修改，之后也没有跟进。
修法：`trigger:'axis'`（formatter 里改用 `params[0].dataIndex`）。

**H4. `engines` 声明错误。（✅ 已修）** `package.json:21-23` 写 `>=22.5`，但 `node:sqlite` 在 22.5–22.12 需要 `--experimental-sqlite` flag，直到 22.13.0 才默认可用（23.x 为 23.4.0）；`fs.globSync`（测试）需 22.0+；`import.meta.dirname` 需 20.11+。应改为 `>=22.13`。另建议把 `--no-warnings`（屏蔽所有警告，包括未来的弃用提示）换成 `--disable-warning=ExperimentalWarning`。

**H5. GLM 余额端点 404 且无熔断。（✅ 已修）** `src/balance.js:26-33` 的 URL 对当前 API 不成立，日志两天内 85 次 `balance glm: HTTP 404`，每 30 分钟带着 Bearer key 请求一次。README 也只承诺 DeepSeek/Kimi。
修法：核对端点或暂时移除；通用地给每个 provider 加"连续 N 次 4xx 后停用直到重启"的熔断，并把状态暴露到健康条。

**H6. 除 `/api/summary` 外的路由没有错误处理。（✅ 已修）** `src/server.js:261-346` 的 `createServer(async ...)`，只有 summary 分支有 `try/catch`（265-273）；`/api/sessions`、`/api/session/:id`、`/api/tool-activity`、`/api/export.csv` 里任何 SQLite 异常（如 `SQLITE_BUSY`：库没有设置 `busy_timeout`，用户在服务运行时执行 `tokenmeter today` 就可能撞上）都会成为未处理 rejection → 进程退出。
修法：一个 `withErrors(handler)` 包装 + 统一 500 响应；`Store` 构造时 `PRAGMA busy_timeout = 3000`。

#### MEDIUM

**M1. Host 头不校验（DNS rebinding）。（✅ 已修）** 服务只绑 127.0.0.1 是对的，但 `curl -H 'Host: evil.example.com'` 返回 200。恶意网页可通过 DNS rebinding 把自己的域名解析到 127.0.0.1 读取 `/api/summary`（含项目名、模型、余额）。修法：`req.headers.host` 不在 `{127.0.0.1, localhost}:port` 时返回 403。

**M2. `innerHTML` 全程无转义。（✅ 已修）** `web/app.js:208、300-303、385、520-530、875-885` 直接拼接 `project`、`model`、`last_error`、`provider`，ECharts formatter（`web/app.js:488-492`、`676`）拼接工具名。这些值来自本地目录名与各工具 transcript，一个名为 `<img src=x onerror=…>` 的克隆仓库目录或被提示注入的工具名就能在面板里执行脚本。当前库里 `project` 无 HTML 字符，属潜在风险。修法：`esc()` 工具函数，所有插值统一过一遍；属性值同样处理。

**M3. Codex 事件与文件游标都以绝对路径为键。** `src/collectors/codex.js:103` 的 `dedup_key = codex:${path}:${seq}`（工具调用同理，`:49`），`files` 表主键也是 `path`（`src/store.js:32-41`）。文件从 `sessions/` 搬到 `archived_sessions/` 后会被当作新文件从 0 解析，同一批事件以新键再插一遍 → 重复计数；旧游标行永远留着（目前 40 条陈旧行，其中 1 条 codex 对应 34 条"源文件已不存在"的事件）。当前恰好没有同名文件同时出现在两个目录，但这是时间问题。
修法：dedup 改用 `codex:${fileId}:${seq}`（`fileId` 是含 uuid 的 stem，全局唯一）；`files` 增加 `file_id` 列，扫描结束对比"本轮枚举到的路径集合"与库内集合，缺失的标记 `deleted_at`（不删事件）；提供一次性重键迁移（`UPDATE events SET dedup_key = …`）。

**M4. 测试：脆弱、依赖公网、覆盖有缺口、没有 CI。（✅ 已修）**
- 第 2 层用正则匹配源码（`test/run.mjs:67-78` 要求 `tooltip:` 出现恰好 6 次、`:86-101` 用括号配对抽函数再 `import('data:…')`），合法重构会误报、错误实现可能通过。
- 第 3/4 层的 `serve` 会真实访问汇率与 LiteLLM 接口（临时 HOME 没有缓存），离线时靠 `Promise.race` 超时兜底，测试时长与结果都受网络影响；`TOKENMETER_TEST` 环境变量（`test/run.mjs:281`）定义了但全仓库无人读取。
- 无测试覆盖：dsh、balance、fx、litellm、rates、recon、health 的 `stale/error` 分支、`_inheritCodexModels`、`/api/export.csv`、`/api/sessions`、菜单栏 JSON 契约。
- `node --check` 不解析 import：`server.err.log` 里 12 次启动崩溃全是 `does not provide an export named 'setOnChange'` 与 `Cannot assign to read only property 'onChange'` 这类模块级错误，现有测试不会拦。
- README 写"可跑在 CI"，仓库没有 `.github/workflows`。
修法见 2.3。

**M5. 文件与函数尺寸。** `web/app.js` 911 行（团队规范上限 800），`renderDensity` 94 行、`renderHeatmap` 90 行、`renderStatus` 86 行；`src/server.js` 的 `startServer` 113 行内联路由。拆分方案见 2.3。

**M6. 发布物与仓库卫生。（✅ 已修）** `npm pack --dry-run` 显示包 1.1MB，其中两份 180KB 的 Mach-O 二进制（`bin/token-watcher-bin` 与 `.app` 内副本）、969KB 截图、`learnings/` 全部随包发布；`.gitignore:2-3` 仍写旧名 `bin/token-stats-bar`，导致编译产物已被提交进 git。修法：`package.json` 加 `files` 白名单（`bin/tokenmeter.js`、`src`、`web`），`.gitignore` 改为 `bin/token-watcher-bin`、`bin/token-watcher.app/`，并 `git rm --cached` 已提交的二进制。

**M7. 汇总查询的重复计算。** 每次 `/api/summary` 会：`buildSummary` 约 12 次查询（`by_day_all` 与 `daySet` 两次全表按天聚合可合并），`computeCosts` 对全表做 3 次 `GROUP BY tool, model`（all/today/7d，`src/pricing.js:111-113`）再加按天一次。现在 ~100ms 可接受，但触发源叠加（SSE 每次更新、前端 60s 轮询、菜单栏 30s 轮询且只用 `today_tokens`），且随事件线性增长。建议：菜单栏改用轻量 `/api/today`；summary 加 5s 级内存缓存（以最后一次 `update` 事件与 `days` 为键）；成本聚合改成一次 `GROUP BY d, tool, model` 后在内存里切 all/today/7d。

**M8. `_inheritCodexModels` 每轮无条件执行。** `src/scanner.js:122` 每次扫描（活跃时每 0.8s）都对 587 个 codex 文件行做 `UPDATE` + `UPSERT`，且不在事务里（`:159-164`）。建议仅在本轮有 codex 文件变更时执行，并包一个事务。

**M9. 静默吞错让页面"假死"。（✅ 已修）** `web/app.js:191-195` 的 `load()` 无错误处理：后端 500 时 `res.json()` 得到 `{error}`，`render()` 在 `s.totals.all_time_tokens` 处抛 TypeError，页面停在旧数据、没有任何提示。`renderToolActivity/loadSessions/showSessionDetail` 也是 `catch { /* 静默 */ }`。建议：顶部错误横幅 + "更新于" 时间变红；`catch` 至少 `console.warn`。

**M10. 命名与注释漂移。**
- `src/fx.js:69-70`：`const fresh = !disk || 过期` 语义是"需要刷新"，名字却叫 `fresh`；`RATE_MIN/RATE_MAX` 在 `:51` 声明却在 `:27、:45` 使用（运行期没问题，阅读时像 TDZ bug）。
- `src/litellm.js:9` 注释说"精确键 > 裸名索引"，`buildIndex`（`:25-42`）只建了裸名索引。
- `src/store.js:65` 注释 `tool_calls` 只列 3 个工具，实际 5 个。
- README 只写 DeepSeek/Kimi 余额，代码有 GLM；README 说"缺失 zstd 自动跳过该源"，实际每个 dsh 文件每轮都抛错并写日志（健康状态因无事件显示为 empty 才没标红）。
- `src/server.js:91` 健康列表硬编码 7 个工具名，与 `config.js` 的 `SOURCES` 双份维护（CONTRIBUTING 也要求贡献者两边改）。

**M11. dsh 依赖外部 `zstd` 可执行文件。** `src/collectors/dsh.js:16-24` 用 `execFile('zstd')`。Node 22.15+/23.8+ 内置 `zlib.zstdDecompressSync`（本机 v24 已验证可用），既然 engines 要提到 22.13，可顺势提到 22.15 并删除这个外部依赖与 README 的 `brew install zstd` 要求。

**M12. 健康自检的 `stale` 会误报（修复阶段 1 时实测发现）。** `src/server.js:102-104` 的判据是"最近 30 分钟有文件写入，但最后一条事件比该文件 mtime 早 30 分钟以上"。实测 ccmr 被标黄，但游标已读到文件末尾（`offset === size === 7,193,299`），也就是解析完全正常——只是这段时间 transcript 只追加了用户消息、工具结果这类**不含 usage 的记录**。长会话里这很常见，而健康条的全部价值就在于"标黄 = 真的出问题了"，误报会直接毁掉这个信号。
修法：把判据从"文件在写"改成"文件里出现了**疑似 usage 的新行**却没有产出事件"——采集器已经在做 `line.includes('"usage"')` 预过滤，把该计数回传（本轮跳过了多少条含 usage 但未入库的行）即可精确判定；或退一步，只在 `offset < size`（游标没追上）时才判 stale。
